# AI 全栈开发平台 MVP 第一版范围确认

## 1. 第一版目标

只验证一条最短可用链路：

**创建项目 → 输入产品想法 → AI 生成 PRD/技术方案/任务 → 选择任务 → 单 Agent 执行开发 → 运行简单测试 → 查看结果**

第一版不追求企业级治理，不实现复杂多 Agent 编排、完整 Git 平台、发布系统和知识库。

## 2. 第一版必须实现

### 2.1 Dashboard

- 展示项目数、需求数、运行中任务、已完成任务。
- 展示最近项目和最近 Agent 执行记录。
- “新建需求”可以进入真实需求录入页。

### 2.2 项目管理

- 创建、查看、编辑、删除项目。
- 项目字段只保留：名称、描述、本地工作目录、Git 仓库地址。
- 项目详情展示需求、文档、任务和 Agent Run。

### 2.3 需求与 AI 文档

- 输入产品想法和补充说明。
- 一次 AI 调用生成：简版 PRD、简版技术方案、任务清单。
- 支持 Markdown 查看和人工编辑。
- 未配置模型 Key 时支持演示模式，返回固定结构数据。

### 2.4 任务看板

- 任务状态：待开始、执行中、待确认、已完成、失败。
- 查看任务目标、验收标准和执行结果。
- 选择一个任务启动 Agent。
- 第一版不实现依赖图、Sprint、工时和多人协作。

### 2.5 单 Agent 开发

- 每次只执行一个编码任务。
- 任务输入包含项目目录、PRD、技术方案、任务描述和验收标准。
- 对接 OpenHands Agent Server；未配置时支持模拟执行模式。
- 展示执行状态、事件日志、修改文件和最终回复。
- 支持取消任务；暂停、断点恢复和多 Agent 并发后置。

### 2.6 简单测试

- Agent 完成后执行项目配置的测试命令。
- 展示命令、退出码、标准输出和错误输出。
- 测试通过后由用户点击“确认完成”。
- 第一版不做覆盖率、测试用例管理、失败归因和自动修复循环。

### 2.7 基础系统能力

- 单管理员登录；不做组织、邀请和复杂 RBAC。
- SQLite 默认存储，部署时可切换 PostgreSQL。
- Agent 日志和关键操作记录。
- Docker Compose 一键启动。

## 3. 点击后显示“敬请期待”

- 审查中心：复杂 G1/G2/G3/G4 审批流。
- 文档中心：多文档类型、版本对比、评论协作。
- Agent 管理：自定义角色、技能、模型路由和预算。
- 代码评审：AI Review、风险分级和一键补丁。
- MR/PR 看板：GitHub/GitLab 双向同步和合并门禁。
- 测试中心：用例库、覆盖率、自动修复和回归测试。
- 运维中心：环境、灰度、回滚、告警和生产发布。
- 知识库：数据源同步、RAG、向量检索和权限过滤。
- 集成中心：Jira、飞书、Slack、CI/CD 和云平台。
- 系统配置、用户权限、审计报表等企业能力。

这些菜单保留当前 UI，点击后统一打开“敬请期待”页面，说明计划能力和后续版本。

## 4. 轻量技术栈

| 层级 | 第一版方案 |
|---|---|
| 前端 | React + TypeScript + Vite |
| 后端 | FastAPI + SQLAlchemy |
| 数据库 | SQLite，保留 PostgreSQL 配置 |
| 异步执行 | FastAPI 后台任务 + 数据库状态轮询 |
| AI 文档 | OpenAI 兼容接口，支持 Mock 模式 |
| 编码 Agent | OpenHands Agent Server，支持 Mock 模式 |
| 实时状态 | 前端每 2 秒轮询，不使用 WebSocket/SSE |
| 部署 | Docker Compose：web + api + agent-server（可选） |

Redis、RQ、Caddy、PostgreSQL、对象存储均不作为本地 MVP 的强制依赖。生产试点时再启用 PostgreSQL 和 HTTPS 网关。

## 5. 建议会话数量

建议共使用 **4 个会话**：当前主会话负责集成，另外创建 3 个执行会话。

### 主会话：集成与产品边界

- 确认 MVP 范围、目录结构和接口契约。
- 处理跨模块冲突、集成、端到端验证和最终交付。
- 不与子会话重复开发同一文件。

### 会话 A：前端 MVP

- 负责 `apps/web/**`。
- 将当前原型迁移为 React。
- 实现 Dashboard、项目、需求、文档结果、任务、Agent 执行页。
- 其他菜单实现统一“敬请期待”。

### 会话 B：后端与数据

- 负责 `apps/api/**`、`migrations/**`。
- 实现项目、需求、文档、任务、Agent Run、测试结果 API。
- 实现 SQLite、单管理员登录、Mock AI 文档生成。

### 会话 C：Agent、部署与验证

- 负责 `apps/agent-adapter/**`、`deploy/**`、`tests/e2e/**`。
- 实现 OpenHands/Mock Agent 适配器、测试命令执行。
- 实现 Docker Compose、环境变量和 MVP 端到端测试。

## 6. 为什么不拆更多会话

- 第一版功能小，超过 4 个会话会增加接口沟通和合并成本。
- 前端页面共享布局与状态，不适合按页面继续拆分。
- 后端实体关系紧密，多个会话同时修改模型和迁移容易冲突。
- Agent 适配、Docker 和 E2E 可以形成独立写入范围，适合单独并行。

## 7. 第一版验收标准

1. 使用 Docker Compose 启动系统。
2. 管理员登录并创建项目。
3. 输入产品想法并生成 PRD、技术方案和任务列表。
4. 选择任务启动真实或 Mock Agent。
5. 页面能够持续显示执行状态和日志。
6. Agent 完成后可以运行测试命令并展示结果。
7. 用户确认后任务变为“已完成”。
8. 刷新页面后项目、需求、任务和运行记录仍然存在。
9. 暂不实现的功能点击后统一显示“敬请期待”。

## 8. 预计周期

- 3 个执行会话并行开发：3～5 个工作日完成首个可运行版本。
- 主会话集成和修复：1～2 个工作日。
- 总计预计：5～7 个工作日完成 MVP。

## 9. 等待确认

确认本范围后，立即创建 3 个执行会话并分配任务。默认采用：

- SQLite 默认运行。
- AI 文档和 OpenHands 均支持 Mock 模式。
- 第一版只允许单 Agent 串行执行。
- 复杂菜单统一显示“敬请期待”。
